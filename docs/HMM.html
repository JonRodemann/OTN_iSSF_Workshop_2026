Interpolation of tracks to a regular time interval

Hidden Markov Models require the data to have a regular time step. Because these positions are calculated from random burst tags, we need to interpolate the tracks to a regular interval. This is the third big decision - how do you parse out the time interval to interpolate the tracks? Our suggestion is to start at twice the average burst interval of the tag to account for possible missed detections.

#store the columns needed for this step
ts_col <- "ts"
id_col <- "tag"
track_col <- "track"
x_col <- "x"
y_col <- "y"

#Create a function that interpolates the tracks from the positions. For this function to work, you need to group the data before running it into unique ID X track combinations

interpolate_track <- function(df_group, dt_seconds = 180) { #The default time of the interpolated tracks is 3 minutes, but you can change that
  # df must contain columns: ts, x, y, plus id/track identifiers
  if (nrow(df_group) < 2) return(NULL)  # can't interpolate single-point tracks
  
  tmin <- min(df_group$ts, na.rm = TRUE)
  tmax <- max(df_group$ts, na.rm = TRUE)
  
  new_times <- seq(from = tmin, to = tmax, by = dt_seconds) #sequence the track out to regular intervals based on your start and end times and the interval you identify in the function
  if (length(new_times) < 2) return(NULL)
  
  # numeric times for approx - makes math easier
  orig_t_num <- as.numeric(df_group$ts)
  new_t_num <- as.numeric(new_times)
  
  # ensure sorted by time - earliest to latest
  ord <- order(orig_t_num)
  orig_t_num <- orig_t_num[ord]
  x_orig <- df_group[[x_col]][ord]
  y_orig <- df_group[[y_col]][ord]
  
  # linear interpolation (NA handling: approx requires finite values) - takes actual points and times, then interpolates the point between the actual points based on actual times
  ok_x <- is.finite(x_orig) & is.finite(orig_t_num)
  ok_y <- is.finite(y_orig) & is.finite(orig_t_num)
  if (!any(ok_x) || !any(ok_y)) return(NULL)
  
  x_interp <- approx(x = orig_t_num[ok_x], y = x_orig[ok_x], xout = new_t_num, rule = 2)$y #The y extracts only the interpolated points
  y_interp <- approx(x = orig_t_num[ok_y], y = y_orig[ok_y], xout = new_t_num, rule = 2)$y

  tibble(
    ts = new_times, #interpolated times
    !!id_col := df_group[[id_col]][1],
    !!track_col := df_group[[track_col]][1],
    x = x_interp,
    y = y_interp
  )
}

#Now let's run it on our data!
interp_list <- dat %>%
  group_by(.data[[id_col]], .data[[track_col]]) %>%
  group_map(~ interpolate_track(.x, dt_seconds = 60), .keep = TRUE)

Filtering track by amount of time in the array

They match pretty well! Now comes the fourth big decision. What tracks are worth keeping in the array? Is a 5 minute track worth it? Probably not because it will only include 5 positions. But, you don’t want to get rid of too much data. For this study, we decided to cut it off at 30 minutes or longer in the array for each track. This represents a good amount of time where we might see two types of behaviors. So let’s filter some more!

id20 <- interp_df %>% group_by(ID) %>% mutate(tott = max(ts)-min(ts)) %>% ungroup()

Prepping the data for HMMs

interp_df_30 <- id20_30 %>% arrange(ID, ts)

hmm_data_30 <- prepData(interp_df_30, type = "UTM", coordNames = c("x", "y"))

hmm_data_30 <- hmm_data_30 %>% filter(!is.na(step) & step > 0) %>% filter(!is.na(angle))

Determining the initial step lengths and turn angles for the model

We have prepped our data. However, it is still not just plug and play. We need to investigate our data to fit general curves to our data to inform the model. We don’t need to do this, but it creates a more informed model based on the original data. We are trying to fit these data into two behavioral states, so we will want to inform the model with 2 curves.

hist(hmm_data_30$step, breaks = 20, freq = F, main = "Step lengths")
curve(dgamma(x, shape = 1.5, rate=0.9), n=200, add=TRUE, col="royalblue", lwd=4) #shape is how right-skewed the gamma curve is
curve(dgamma(x, shape = 1.9, rate=0.6), n=200, add=TRUE, col="cadetblue", lwd=4) #rate is how tall the curve apex is
curve(dgamma(x, shape = 2.2, rate=0.4), n=200, add=TRUE, col="navyblue", lwd=4)

#assign initial step length distributions
sl_init_mean <- c(1.9/0.6, 1.5/0.9) #initial means should be the shape/rate for both
sl_init_sd <- c(sqrt(1.9)/0.6, sqrt(1.5)/0.9) #initial standard deviations should be square root of shape/rate

This is a little subjective, but there is a good starting out point. The first curve encompasses the lower step lengths well.The third curve does not really do a good job because it is spread out too far. So let’s go with the first and second curves

Now we do the same thing for the turn angles. However, we want the model to try to find states with opposite turn angles (turn 180 degrees vs straight). Therefore, we will play with the numbers a little.

The first curve is almost a straight line. But we want the model to try to fit 180 degree turn and straight. The second curve is straight ahead and the first is the turn around. It needs to be as close to flat as possible to fit the data the best.

Looking at the step length and angle distributions, you can see a few things. State 1 is categorized by longer step lengths (average of 4 meters) and straight turn angles (0.007 radians, basically zero). State 2, on the other hand, has a much shorter step length (average of 0.9 meters) but a similar turn angle (-0.02 radians). However, the concentration is a lot lower, so state 2 encompasses the larger turn angles. These results also give you a transistion probability to transition between states. Pretty low for both, but it does happen. If you run the following code, you can visualize the distributions for each state as well as which state each step on all the tracks is!
